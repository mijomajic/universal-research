# Keyword / search-demand mode

Query-space research. Useful for SEO, but also for "what do people type when they have this problem?" Do not reduce every research task to keywords.

## What this mode is for

Query discovery, intent, clustering, long-tail expansion, SERP analysis, competitor coverage, topic relationships, informational vs commercial intent, demand proxies, ranking-difficulty proxies, topical coverage, question discovery, recency sensitivity.

## Method

1. **Seed** — user language, product names, jobs, synonyms, questions.
2. **Expand** — related queries, People Also Ask-style questions, typos only if they carry demand.
3. **Cluster by intent** — know / do / buy / navigate. A cluster is a shared intent, not a shared word.
4. **Open SERPs** — for representative queries, who ranks and what format wins (guide, tool, video, forum). Household Firecrawl **search was not verified**; use whatever discovery the doctor allows (Agent Reach/Exa, engine in a browser, etc.). Do not call Cloud search.
5. **Coverage** — which clusters competitors already own; which questions have weak results.
6. **Difficulty / demand** — treat third-party volumes as **proxies**. Directionally useful, not census data.
7. **Recency** — newsy queries vs stable head terms.

## Sources

Autocomplete, SERPs, Search Console if the user has it, app-store search, community phrasing (Reddit) as language seeds. Community phrasing is not search volume.

## Output

A keyword map: cluster → example queries → intent → SERP notes → gap. Not a 2,000-row dump unsorted.

## Pitfalls

- Optimizing for a head term the SERP cannot be won with, without saying so.
- Mixing locales.
- Equating Reddit wording 1:1 with Google demand.
